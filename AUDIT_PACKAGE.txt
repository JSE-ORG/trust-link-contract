================================================================================
                       THREAT CHECKLIST
================================================================================

AUDIT AGAINST THESE 13 THREATS:

1. ✓ Unauthorized Fund Release
   - Verify require_auth precedes all transfers

2. ✓ Role Confusion Attack
   - Check buyer ≠ seller ≠ resolver validation

3. ✓ Fee Arithmetic Overflow
   - Verify checked_mul/div throughout

4. ✓ Dispute Window Bypass
   - Validate dispute window guard

5. ✓ Token Callback Reentrancy
   - Check state updated before transfer

6. ✓ Dispute Fee Deduction Order
   - Verify arbitration fee deducted first

7. ✓ Storage TTL Expiration
   - Validate TTL extension before writes

8. ✓ Timestamp Manipulation
   - Understand network-level protections

9. ✓ Pause Function Abuse
   - Verify pause is toggleable

10. ✓ Invalid Evidence Hash
    - Check 32-byte validation

11. ✓ Arbitration Fee > Amount
    - Verify fee caps (max 10%)

12. ✓ Multiple Concurrent Disputes
    - Validate state prevents duplicates

13. ✓ Delivery Before Dispute Closes
    - Understand by-design behavior

(See THREAT_MODEL.md for full analysis)

================================================================================
                       INVARIANT CHECKLIST
================================================================================

VERIFY THESE 15 INVARIANTS:

1. ✓ Balance Conservation - Total tokens = sum of escrows
2. ✓ Escrow ID Uniqueness - No ID collision possible
3. ✓ State Machine Validity - Only approved transitions
4. ✓ Role Separation - Buyer ≠ seller ≠ resolver
5. ✓ Authorization Ordering - Auth before state reads
6. ✓ Fee Monotonicity - Deterministic fee calculation
7. ✓ Amount Conservation - Payout + fees = original amount
8. ✓ Buyer Assigned at Fund - Buyer always Some for Funded+
9. ✓ Storage TTL Consistency - No data loss mid-tx
10. ✓ Dispute Window Non-Overlap - Windows independent
11. ✓ Resolver Immutability - Resolver cannot change
12. ✓ Counter Monotonicity - Counter only increases
13. ✓ Pause State Isolation - Pause doesn't corrupt data
14. ✓ Token Transfer Atomicity - All-or-nothing tx
15. ✓ Evidence Hash Immutability - Evidence cannot change
